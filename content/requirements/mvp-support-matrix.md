# Initial MVP scope and support matrix

Status: **bounded local Luma hero/grid and guest-cart experiment observed; no beta support matrix declared**.
Date: 2026-09-07. Owner: [SOL-491](https://linear.app/solventech/issue/SOL-491).
Customer discovery [SOL-490](https://linear.app/solventech/issue/SOL-490) remains Todo and informs
the final beta promise. Local development can proceed on the confirmed hybrid direction.

[Batch 03A](../roadmap/batch-03a-evidence-2026-09-07.md) exercised base/CMS 2.4.6-p13 packages,
Luma 100.4.6-p13 and PHP 8.2.29 on an isolated generated fixture for one explicit home hero region.
Installation, selection and original restoration passed with untouched-route comparisons. This
as-installed package subset, disabled-FPC context and single store/simple-product fixture do not
establish full Magento/Luma support. [Batch 03B](../roadmap/batch-03b-evidence-2026-09-07.md) extends the same fixed home region to a native grid with live prices and simple/configurable guest-cart proof on the 182-package fixture. Hyvä, Porto, hosted product-grid editing, handshake/preview, durable
publication, multiple contexts and the wider commerce/cache matrix remain unverified.

## First merchant outcome

Keep the active theme, connect deliberately, select a store/home or CMS page, edit a hero and
product-reference grid, preview through Magento, publish only that target and restore it without
changing another page or commerce. A registered region is allowed only when a native adapter
declares its boundary. A free reference theme is optional for this outcome.

| Surface or content | Initial classification | Required evidence |
| --- | --- | --- |
| Home/CMS hero and product grid | Planned editable through registered Luma/Hyvä adapters | Exact fixtures, preview fidelity, independent publish/restore and outage tests |
| Registered region in existing theme | Planned adapter-mediated editing of declared fields | Single owner, original snapshot, scoped CSS/JS and unaffected sibling behavior |
| CMS block and registered widget | Reference-only initial contract | Native rendering, escaping, cache identities and supported parameter resolution |
| Supported Page Builder structures | Later explicit conversion, with dry-run/original retention | Mapping fidelity, no double output and coherent restoration |
| Arbitrary PHP/HTML/extension markup | Unsupported structural editing; preserve original | Clear integration requirement and blocked incompatible activation |
| PDP and category pages | Reserved contract targets; adapter rollout follows home/CMS proof | Selected and adjacent page comparisons, simple/configurable behavior and native prices/cart |
| Header/footer, search/navigation, account, mini-cart, cart, checkout | Untouched shared/native surfaces in initial hybrid scope | Before/after checks after install, publish and restore |
| Theme-wide token/header/footer controls | Future reference-theme or explicit adapter work | Scoped effects, foundation rights and separate support evidence |

The initial JSON vocabulary includes hero, product-grid, CMS-block and widget references. Future
text/image/FAQ/announcements and category/review presentations are not automatically supported
because they appear in broader research. No checkout replacement, universal conversion, Liquid,
headless renderer or marketplace delivery is included in the first outcome.

## Version and context decisions still open

| Dimension | Batch 01 decision | Gate before support claim |
| --- | --- | --- |
| Magento Open Source patch | Unselected | Customer need, current vendor requirements, dependency review and clean fixture lock |
| PHP, database, search, cache, web server | Fixture-specific exact versions required | Match the selected Magento row; host availability alone is insufficient |
| Luma | Preserve installed active theme; native adapter planned | Pin actual theme/module package versions and overrides in fixture evidence |
| Hyvä | Separate native adapter; no borrowed entitlement | Obtain product-owned package access/rights and pin version/dependency lock |
| Products | Simple/configurable are initial proof candidates | Prices/options/cart behavior observed in both fixture themes |
| Store views and locales | Two exact stores; default-source drafts materialized before publication | No preview leaks, independent assignments and correct inherited-value presentation |
| Currency/customer groups | Two currencies and guest/test group contexts in fixture | Warm/cold FPC and private-content correctness without frozen commerce data |
| Device/CSP/accessibility | Desktop/mobile and strict CSP proof required | Real native rendering and editor keyboard/accessibility tests |

The [fixture plan](../architecture/integration-fixtures.md) identifies exact missing access and
reproducibility artifacts. SOL-491 stays In Progress: this scope and contract foundation do not
